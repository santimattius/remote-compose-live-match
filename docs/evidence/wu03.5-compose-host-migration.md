# WU3.5 — Jetpack Compose host migration + real WU3 gate re-run

## Context and decision

WU3.4 root-caused the "blank render" symptom that had blocked WU3–WU3.3: a plain `android.app.Activity`'s default opaque `ActionBar` composited over the full-screen `RemoteComposePlayer`, hiding its content. WU3.4's fix was an imperative `actionBar?.hide()` diagnostic workaround.

The user asked to review the theme/style properly, initially under the (corrected) impression that the project already used Jetpack Compose. It did not: `MainActivity`/`DiagnosticPlaybackActivity` extended plain `Activity`, there was no `app-android/src/main/res/` directory, and `buildFeatures.compose` was never enabled — the only "Compose" in the app module was `androidx.compose.remote` (Compose *Remote*, a document-rendering library unrelated to Jetpack Compose UI). Given a choice between a minimal `NoActionBar` theme on the existing View-based Activity, or migrating the host to real Jetpack Compose, **the user explicitly chose the Compose migration.**

`RemoteComposePlayer` (from `remote-player-view`) is a plain `View`, not a `@Composable`, so "migrate to Compose" means: convert both host activities to `ComponentActivity` + `setContent {}`, embed the player via `AndroidView` interop, and apply a proper (`NoActionBar`) theme — switching to `ComponentActivity` alone does not remove a legacy ActionBar without a matching theme.

## Scope delivered (single work unit, not split)

1. **Dependencies** (`gradle/libs.versions.toml`, `app-android/build.gradle.kts`): added `org.jetbrains.kotlin.plugin.compose` (required separately from the Kotlin plugin since Kotlin 2.0+), `buildFeatures.compose = true`, `androidx.compose.ui:ui`, `ui-tooling-preview`, `androidx.compose.material3:material3` (via the already-pinned `compose-bom = 2025.04.01`, previously unused), and `androidx.activity:activity-compose`.
2. **Theme**: new `app-android/src/main/res/values/themes.xml` (`Theme.LiveMatch` extends `android:Theme.DeviceDefault.NoActionBar` — a platform theme was chosen over `Theme.Material3.*NoActionBar` from `com.google.android.material:material` to avoid pulling in the legacy Material Components library the project doesn't otherwise depend on), wired via `android:theme` on `<application>` in `app-android/src/main/AndroidManifest.xml`. This is the real, declarative fix for the occlusion — the debug manifest's `<application>` has no theme override, so it inherits this through manifest merging.
3. **`MainActivity`**: rewritten as `ComponentActivity` + `setContent { MaterialTheme { Surface { AndroidView(factory = { ctx -> RemoteComposePlayer(ctx).also { loadScheduledFixture(it) } }) } } }`. The document loads once, inside `factory`, so it is not reloaded on recomposition.
4. **`DiagnosticPlaybackActivity`**: migrated the same way, preserving the exact `pre_attach`/`post_attach` mode contract and both fixture names. `pre_attach` loads synchronously inside `factory` before the view is returned; `post_attach` schedules `player.post { load(...) }`, the same deferred mechanism as the original View-based implementation, so the WU3.1 pre/post-attach timing contract is preserved rather than approximated via Compose's own composition timing. The imperative `actionBar?.hide()` workaround from WU3.4 is removed — the theme now makes it unnecessary.
5. **Text-color production fix** (`creator-jvm/.../ProceduralJvmMatchDocumentCreator.kt`, incidental bug found in WU3.4): the creator drew team-name/kickoff-time text via `drawTextAnchored(...)` without ever calling `getRcPaint().setColor(...)` first. Fixed by explicitly setting `getRcPaint().setColor(BACKGROUND_COLOR).setAntiAlias(true).commit()` before `drawRect` and `getRcPaint().setColor(TEXT_COLOR).setAntiAlias(true).commit()` before the three `drawTextAnchored` calls, reusing the same navy (`0xFF002B5C`) established as this project's diagnostic-probe background for visual consistency, and white (`0xFFFFFFFF`) for legible contrast.
6. **Canonical fixture regenerated**: `fixtures/scheduled-match.rc` bytes and SHA-256 changed because the creator's output changed (expected — colors are now explicit encoded operations in the document). Old: `57884b403add2d49825b89d71e6257fbc5a15cd66f51581890a8442b54741d51`. New: `2feee2fa05b3fe13bb9b21e90269212ad3620ee91f3d00e5afb85e30cb555447`. `fixtures/scheduled-match.manifest` regenerated to match.
7. **Existing instrumentation tests updated** (`ScheduledFixturePlaybackTest.kt`, `DiagnosticPlaybackTest.kt`): both asserted `root.getChildAt(0) is RemoteComposePlayer` on `android.R.id.content`. Under Compose, that child is now a `ComposeView`/`AndroidComposeView`, not the player directly. RED was reproduced for the real reason (see below) before fixing: both tests now do a small recursive `findRemoteComposePlayer(view)` search of the view tree instead of a single `getChildAt(0)`. `ScheduledFixturePlaybackTest`'s `EXPECTED_SHA256` constant was updated to the new fixture hash.
8. **Real WU3 gate re-run**: rebuilt, reinstalled, and captured fresh device evidence for the actual `MainActivity` + `scheduled-match.rc` (not just diagnostic fixtures) — this is the first genuine visual GO for the original WU3 gate.

### Screenshot and pixel result (full 1080×2424 frame; no chrome to exclude now that the ActionBar is gone)

- **`MainActivity` / real `scheduled-match.rc`** (`wu03.5/main-activity.png`): navy `#002B5C` — 54,840 px (2.0948%); white `#FFFFFF` (text) — 2,399 px (0.0916%). **Both the background and the team-name/kickoff-time text are visible.** This is the first genuine visual GO on the original WU3 gate. The document's own declared 320×180 logical viewport is drawn at the player's origin without upscaling to fill the screen — expected for this scoreboard-sized document, not a defect. The document content also starts flush at `y=0`, extending into the system status-bar area; this is standard edge-to-edge behavior once no ActionBar/window-inset handling is in play, consistent with API 35's edge-to-edge defaults, and out of scope for this WU (no WindowInsets handling was requested).
- **`paint-probe.rc` post-attach** (`wu03.5/post-attach-paint-probe.png`): navy 44,043 px (1.6824%), yellow 11,119 px (0.4247%) — consistent in magnitude with WU3.4's cropped-frame baseline (1.65%/0.44%), confirming the Compose migration does not regress this fixture.
- **`alpha18-api6-control.rc` post-attach** (`wu03.5/post-attach-alpha18-api6-control.png`): full black circle, 68,111 px (2.6017%) — consistent with WU3.4's 2.59%, confirming parity; this is a full circle, not the earlier clipped arc.
