**WU8** started the deferred pipeline work (actions/envelope/cache) with the action catalog. Built and tested `MatchPhase`/`ActionId`/`ActionAllowlist` in `contract` (table-driven, matches spec 6.3's allow table exactly) and wired `MainActivity` to receive document-emitted actions via `RemoteComposePlayer.addIdActionListener`, validating against the allowlist before ever reaching further logic. Added a real "Remind me" button + `addClickArea` call to the Scheduled document — confirmed it doesn't regress rendering, but could **not** confirm the tap actually reaches the listener end-to-end (tested with both the plain writer and WU3.2's API-6 writer variant, same null result). See `docs/evidence/wu08-action-allowlist.md` for the full investigation and the working (unconfirmed) hypothesis about a component/modifier-DSL requirement.

**WU9** found and fixed the real root cause: **not** a library/DSL limitation, but a one-line host-side ordering bug. `MainActivity` called `player.addIdActionListener(...)` **before** `RemoteComposePlayerAdapter().load(...)` (`setDocument`); since `RemoteComposePlayer.setDocument` replaces the internal `CoreDocument` instance, the listener registered beforehand was silently orphaned on the discarded document. Reordering to register the listener *after* loading the document fixed it completely — a real on-screen tap (`adb shell input tap`) on the Scheduled "Remind me" button now reaches `MainActivity`, resolves to `ActionId.SET_REMINDER`, and passes `ActionAllowlist`. WU8's `uiautomator dump`-based "no `ClickAreaView`" evidence was also a false signal (`uiautomator` doesn't reflect this accessibility-invisible view; reflection on the live view tree showed it there all along, correctly bounded and clickable). WU8's action-catalog/allowlist logic needed no changes. See `docs/evidence/wu09-click-area-root-cause.md` and `docs/alpha-learnings.md`.

**WU10** extended the same proven pattern to the remaining catalog actions: a "Match"/"Highlight" button pair (`open_match`/`open_highlight`) added to the Live document (its viewport grew from `1080x480` to `1080x600` to fit both buttons below the existing score/clock text without overlap) and a "Summary" button (`open_summary`) added to the Finished document, both via `RemoteComposeWriter.addClickArea` mirroring WU9's Scheduled button exactly. `DiagnosticPlaybackActivity` (the only host that loads Live/Finished today) gained the same `addIdActionListener`-after-`load()` wiring as `MainActivity`, dispatching through the existing `ActionAllowlist` with the phase matched to the loaded fixture. Hit and resolved a new alpha19 finding along the way: loading a document via the diagnostic activity's `MODE_POST_ATTACH` path registered the click areas at the document-model level but never materialized their `ClickAreaView` children (reflection showed `getClickAreas()` returning the correct count while the live view tree had zero children) — switching to `MODE_PRE_ATTACH` (the same timing `MainActivity` already uses) fixed it; see `docs/alpha-learnings.md`. All three actions confirmed with real on-screen taps: `Accepted action: open_match`, `Accepted action: open_highlight`, `Accepted action: open_summary`.
